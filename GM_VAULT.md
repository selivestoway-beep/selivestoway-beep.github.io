# Отдельный сейф ГМа

## Что изменилось

В «Кодексе Термины» появились **два независимых ключа**:

1. **Ключ читателя** расшифровывает `data/articles.enc.json` — энциклопедию, доступную игрокам.
2. **Пароль сейфа ГМа** расшифровывает `data/gm-vault.enc.json` — отдельный файл с приватными заметками по статьям. Впервые файл создаётся из интерфейса ГМа. Он не входит в общий файл статей.

Оба файла находятся в публичном GitHub-репозитории **в зашифрованном виде**. Сведения внутри сейфа доступны только тому, кто знает его пароль; GitHub-токен сам по себе не расшифровывает сейф. Пароль сейфа должен отличаться от общего ключа, состоять минимум из 16 символов и после ввода хранится **только в памяти текущей страницы**, без записи в браузерное хранилище. После обновления страницы нужен повторный ввод.

> Это криптографическое разделение **для новых заметок в сейфе**. Данные, ранее размещённые в общей базе как `:::гм`, `:::секрет` или в старых версиях файлов, по-прежнему потенциально известны обладателям старого общего ключа.

## Начало работы

1. Откройте опубликованный сайт, разблокируйте общую энциклопедию и войдите в раздел **«Вход для ГМа»** с GitHub fine-grained токеном, имеющим запись в текущий репозиторий.
2. Нажмите **«Сейф ГМа»**, создайте новый длинный пароль (отдельный от ключа энциклопедии), подтвердите и сохраните его в менеджере паролей. Восстановить его через GitHub нельзя.
3. Выберите статью, впишите приватные заметки и нажмите «Сохранить секрет отдельно». На странице статьи при открытом сейфе заметки отображаются только ГМу.
4. Когда работа закончена, нажмите **«Закрыть сейф»**. При выходе из аккаунта ГМа содержимое сейфа также удаляется из памяти страницы.

**Не** добавляйте новые секретные блоки `:::гм` или `:::секрет` в поле обычного редактора статей: запись таких блоков теперь запрещена.

## Перенос прежних блоков `:::гм` и `:::секрет`

Перед переносом рекомендуется сделать резервную копию репозитория. Операция изменяет общую энциклопедию в двух последовательных коммитах GitHub:

1. Сначала все найденные блоки копируются в **зашифрованный сейф**. Существующие заметки при этом сохраняются.
2. Только **после успешной записи сейфа** эти блоки убираются из текущей версии `data/articles.enc.json`.

В интерфейсе **Сейф ГМа** отображается число статей со старыми блоками. Наберите `ПЕРЕНЕСТИ` и нажмите кнопку. При конфликте версий, ошибке сети или отказе GitHub содержимое, уже записанное в сейф, не удаляется. После ошибки проверьте записи и повторите операцию. Маркеры импорта помогают избежать повторного добавления одних и тех же блоков.

Важные ограничения:

- В проекте есть отдельные зашифрованные файлы истории `data/hist/*.enc.json`, а GitHub хранит старые коммиты. Перенос текущей версии **не очищает эти файлы**, старые коммиты, кэш браузера и сделанные ранее копии.
- Обладатели старого общего ключа могут по-прежнему прочесть исторические копии. Для закрытия **старых** секретов придётся отдельно обработать историю и сменить общий ключ с перешифрованием всех доступных старым ключом файлов. Даже удаление истории не отзывает ранее скачанные копии.
- Секреты, которые уже увидели игроки, нельзя сделать «неувиденными».
- Публикация на GitHub Pages может обновиться с задержкой.
- Если необходимо безусловное серверное разграничение ролей и отзыв доступа пользователей, статический GitHub Pages не заменяет серверную авторизацию.

## Проверка изменений

В GitHub Actions запускаются тесты `node --test tests/*.test.mjs` для синтаксиса, удаления GM-блоков только после копирования, сохранения публичного текста и защиты от невалидных блоков. Для шифрованной базы без ключа автоматические тесты не расшифровывают пользовательские статьи.

## Проверка после выпуска

На отдельной тестовой статье проверьте создание сейфа, запись заметки, выход из ГМа, чтение как обычный игрок и повторное открытие с отдельным паролем. Только после этого запускайте перенос старых блоков; не проводите миграцию вслепую.
