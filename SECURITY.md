# Безопасность «Кодекса Термины»

## Как устроен доступ

Сайт опубликован как статический GitHub Pages. Файлы `data/*.enc.json` и `data/hist/*.enc.json` находятся в **публичном** репозитории, но их содержимое зашифровано в браузере с использованием AES-GCM и ключа, выводимого из парольной фразы (PBKDF2/SHA-256).

Ключ энциклопедии может передаваться в ссылке вида `#k=...`. После открытия кодекса сайт убирает этот фрагмент из адресной строки и сохраняет ключ на время сеанса вкладки.

Это шифрование обеспечивает защиту только пока парольная фраза неизвестна посторонним. Доступ к репозиторию **не равнозначен** доступу к расшифрованным статьям.

## Разграничение ролей — важное ограничение

Блоки `:::гм` / `:::секрет` скрываются **только средствами интерфейса**. Если читатель уже получил ключ для расшифровки общей базы статей, весь текст статьи, включая скрытые блоки, оказывается в памяти его браузера.

**Не размещайте в этих блоках информацию, которую необходимо криптографически скрывать от игроков.** Для настоящего разграничения доступа понадобится отдельное хранилище ГМа с отдельным ключом / серверная авторизация.

## GitHub-токен ГМа

Редактирование с GitHub Pages требует права записи в репозиторий. Используйте GitHub fine-grained personal access token с доступом только к этому репозиторию и минимально необходимым разрешением `Contents: Read and write`. Токен не должен попадать в статьи, коммиты, переписки, логи или скриншоты.

Сайт хранит токен и парольную фразу в `sessionStorage`, а не в `localStorage`. Старые значения из `localStorage` переносятся однократно и удаляются. Это ограничивает срок хранения, но **не защищает от вредоносного JavaScript на самой странице**: работающий код сайта может читать `sessionStorage`.

Кнопка «Выйти» удаляет сохранённый токен ГМа. Для закрытия доступа к содержимому энциклопедии завершите сеанс вкладки.

## Если ключ или токен попал к посторонним

- **GitHub-токен:** отзовите его в настройках GitHub и создайте новый с минимальными правами.
- **Ключ кодекса:** замените парольную фразу и **перешифруйте все** зашифрованные файлы. Простая смена ссылки не сделает уже опубликованный шифротекст недоступным тому, кто знает старый ключ.
- **Секреты ГМа в общей базе:** считайте их раскрытыми любому, у кого есть ключ читателя.

## Проверки

В репозитории есть базовые проверки `node --test tests/*.test.mjs` для синтаксиса приложения, устойчивости маршрутов, миграции ключей и целостности формата зашифрованных файлов. Проверки не заменяют ручное тестирование страниц и аудит безопасности.
